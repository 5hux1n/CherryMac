# 宏录制移植（源码进展）

客户端宏页提供独立录制窗口，网页宏页提供可展开的录制区；默认采用当前录制区收到的键盘／鼠标按钮事件；客户端另提供可选的其他应用录制，只有明确开始该模式后才安装观察监听，不触发 HID 写入。系统或浏览器截获的快捷键、无法唯一识别的键位请手动添加。该增量尚未加入 Mac 0.11.0／Web 0.5.0 下载包。

## 时序与数据

纯状态机支持实际间隔、固定间隔及忽略间隔；时间由调用端的单调时钟提供。新录制的间隔放在前一个事件上，末事件为零；启动录制至首事件的等待不加入宏。固定间隔作用于相邻事件之间。导入旧宏时保持各事件 Delay，不重新覆盖。实际间隔按官方录制路径限制为最多 60000 毫秒。完成后保存固定间隔录制选项，忽略间隔直接体现为事件零延迟。

依据官方 `0x449A70–0x449AB3` 的模式设置及 `0x45B40B–0x45B4AB` 的延迟生成分支：模式 2 使用固定值，模式 3 为零，模式 1 使用计时间隔并限制上限。现有本型号宏区组装继续使用每个事件的序列化字节。

开始录制前检查并要求松开修饰键。长按重复不新增步骤；开始前已按住的键，其孤立释放不录入。键盘和鼠标分别配对；未完全释放时停止会提示继续释放，不能采用不平衡步骤。取消、局部录制失焦、切换页面或容量错误丢弃本次录制，保留原编辑步骤；不合成释放、不静默补齐。上限仍为 256 事件与整个宏区容量校验。

原生 Control／Shift／Option／Command 左右侧状态使用 macOS SDK `IOKit/hidsystem/IOLLEvent.h` 的设备修饰键位掩码。无法从 AppKit 唯一判断的虚拟键编码拒绝录制，保留手工输入能力；不能据此声明原始 USB 事件完全捕获。

## 离线检查

原生 16 组自测通过，新增三种间隔的黄金事件序列、重复过滤、未释放停止拒绝、失焦取消及原生录制窗口普通键／Control 组合键适配检查。网页核心 29 项通过；Chrome 页面检查覆盖固定间隔录制、未松开停止后继续、保存与导出、切页取消、鼠标按钮录制与原步骤保留。浏览器自动化事件作为界面适配证据，不视为用户实体按键或宏固件执行证据。现有 15 组两端 Windows 混合宏转换一致性仍通过。

## 滚轮核对状态

公共动作表中的 Type 4／5 对应 X／Y 移动，控件为 `kb_mouse_x_left_edit` 等，不能套作滚轮。虽公共表包含消息 020A，已追踪的宏鼠标录制函数 `0x45BC40` 在 `0x45BF86` 只搜索六个基本按钮事件，另处理 020B／020C 的扩展按钮，其他消息在 `0x45C34E` 走清理返回。手工宏菜单也仅列五个鼠标按钮。这些证据尚不足以排除其他入口或型号分支支持滚轮，继续核对，不猜测滚轮方向与步数。

文本动作、本型号功能对照、录制完整性及写入／恢复产品流程继续推进；完成宏代码审查与离线校验后，再按用户顺序进行真机写入、执行和断电保留测试，然后推进灯效。

## 步骤排序（源码进展）

官方 MacroControl 资源包含 `macro_btn_uptop`、`macro_btn_up`、`macro_btn_down`、`macro_btn_downbottom`。两端现在提供置顶、上移、下移和置底：客户端选中文本中的一个步骤后使用下方按钮；网页在步骤行的“移动…”菜单选择位置。排序只修改编辑中的事件顺序，事件按键、状态、延迟不变；保存仍要求按下／松开配对，不自动补释放。

原生离线界面检查验证置底与置顶往返、选中步骤与顺序保持；17 组核心及 3 组研究检查通过。Chrome 实际表单检查把松开移到按下之前，确认保存拒绝，再恢复顺序并保存；同时覆盖来源字段保存、播放模式、109 个方形键位、窄屏和模拟普通键写入，页面无脚本错误。原生宏页已渲染并目视核对。未连接实体设备，发布包未更新。


## 已有输出日志的间隔复核

未新增真机操作。回看通过的 Shift+A 实体 USB 日志，四个事件原始 Delay 为 0、80、80、80，实际相邻间隔为 1、81、81 毫秒；此前 AB 三次和鼠标中键输出也显示首段约 1 毫秒。这些捕获支持 Delay 在当前事件后等待，不能证明所有延迟值的精确回放。新录制器据此将相邻事件间隔写入前一步，末步为零；导入／导出原始事件、既有用户宏及研究场景保持原 Delay。录制黄金期望同步调整，精确时序与录制后实体回放留待宏模块统一验收。

## 步骤前后插入

两端新增插入位置选择，默认末尾追加。客户端点选步骤编辑器可在所选步骤前／后添加按下、松开事件；网页在“添加按键”旁选择步骤前／后。插入保留其余事件及延迟，达到 256 事件上限时拒绝添加且保留草稿；采用／保存仍检查事件配对。客户端插入沿用所选步骤的按键或鼠标按钮，网页使用“添加按键”的选项。网页录制期间禁用插入位置控件。

必要原生编译及宏编辑专用检查、网页保存表单检查通过，覆盖前后插入位置与原延迟保留，无 HID 请求。源码变更尚未进入此前预览包，统一验收前一起更新。

## 录制片段的追加与插入

官方宏菜单另有 `redio_previous_record_time`／`redio_later_record_time` 及忽略间隔选项。两端现在可选择替换全部、末尾追加或在指定步骤前／后插入新录制片段；客户端以打开录制窗口前的文本光标所在步骤为选择，网页直接选择步骤编号。开始时冻结原步骤与插入位置，录制期间不可编辑它们。采用时合并并检查数量与按下／松开平衡，原事件的 Delay 不重写，新片段按所选录制间隔计算，尾事件仍为零。

未录制操作、插入越界、合并超 256 事件或配对失败均不采用；失败不会使录制器进入无法再次停止的状态。取消和失焦保留原编辑步骤。必要纯模型检查、原生宏编辑检查及网页实际表单检查通过，覆盖录制前插入和原延迟保留，没有全局输入钩子或 HID 请求。这项能力仍是录制区内的采集，不宣称复刻全局录制。

## 客户端其他应用录制（代码待实机验收）

客户端录制窗口新增默认关闭的其他应用录制选项。开启时要求辅助功能权限；只检查授权，不自动弹出申请或改变系统设置。开始后通过 AppKit 全局事件观察记录其他应用的按键、左右修饰键及可选的五种鼠标按钮，本 App 内仍只录制指定区域，避免将停止按钮的点击写入宏。全局模式切换应用不取消；局部模式失焦仍取消。操作会正常发送给原应用，鼠标模式也会记录切换应用的点击。

停止成功、取消、关闭窗口、容量／未知键位错误或不支持的鼠标事件都会移除监听。未松开按键导致停止失败时保留录制，允许松开后再停止。系统安全输入、权限变更或被系统截获的事件可能无法收到，不保证完整捕获；仍支持手动补充。网页受浏览器范围限制，保持页面内录制。

本轮仅编译与离线适配检查：模拟外部按键路由、全局模式失焦保留、结束清理，以及未授权时拒绝开始。检查未安装实际监听、未触发权限申请、未接触 HID。真实跨应用捕获与宏回放待整个宏模块统一验收。

## 2026-10-10 实体观察的原始鼠标报告留档

## 2026-10-10 保存日志的鼠标字段解码

新增离线工具 `Tools/inspect-mouse-observation.py`，输入上述原生观察窗口的 version2 session.json，按日志随附描述符解码 Report2，不连接设备或发送报告。工具检查描述符 SHA256、报告来源 registryID、原始长度与回调结果；兼容六字节 payload 和带正确 ReportID 的七字节原值，不猜测其他长度或旧固件字段顺序。输出保留各字段 Usage、位偏移、逻辑范围、相对／绝对标志及范围异常计数；解码成功不等于宏执行或断电验收通过。

共享描述符解析器现在保留一个字段的全部显式 Usage 及有符号逻辑范围，拒绝尚未支持的 Usage delimiter。已保存的本型号真实描述符静态解析得到按钮 offset0、滚轮 offset8、X/Y offset16／32；滚轮范围 −127..127，X/Y 范围 −32768..2047，不能假设对称范围。此前只保留最后一个显式 Usage，会丢失 X 的标识，已修正。

## 2026-10-10 Report2原始值与原始包的离线关联

研究观察窗口session升version3，新增rawMouseValues：记录系统实际交付的ReportID2 value回调，在MacroHIDObservationAdapter过滤之前保留usagePage／usage／value／时间戳和同一registryID；包括系统交付的零位移、重复按钮及滚轮等未成为宏事件的值。旧rawValues明确标为过滤后的宏事件投影，不当作完整HID回调序列。记录仅在source=hid、phase=observing时进行，校验报告来源／时间与容量，最多65536值，失败保存并停止；不承诺系统会交付每个描述符字段或每次重复值。

## 2026-10-10 观察日志保存合并与终态顺序

独立观察窗口将过滤后事件、Report2原始包和过滤前值先追加内存并标记待保存，由现有100ms定时检查在距离上次保存至少250ms且有新增记录时尝试刷新，避免每个HID字段都重写增长的完整JSON。开始、停止确认、结束、失焦／断开／容量异常等失败和最终通过继续立即保存。定时器及文件I/O可能延迟，250ms是合并阈值而非硬实时／掉电承诺；进程被强制终止会丢失尚未刷新的记录，政策写入session。

保存顺序改为baseline（首次）→execution→assessment→session，session最后记录两份派生日志的精确SHA256；单文件仍使用atomic写入，这不是跨文件事务。只有全部写入成功才清除pending标记、推进上次保存时间、显示观察通过。停止确认和定时／最终日志写入失败明确归类loggingFailed，终止观察，不再按reportRejected混淆为实体输出异常。旧文件或hash本身不证明当前会话／宏执行或断电通过。
