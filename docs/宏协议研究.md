# 官方宏协议的离线分析

分析对象为用户提供的 CHERRY Utility 2.3.28.7 Windows 安装程序中主程序。下面是本地静态分析结果，不是官方公布的协议，也没有通过键盘宏实测。仓库不分发官方程序或反汇编全文。

## 宏写入路径

主程序中宏配置序列化调用 `0x4DBD90`，普通固件生成 Report 4 / 命令 `15`；另一固件分支使用 `95`。生成分块长度、两字节偏移、标志 00、内容，并计算请求校验后调用 HID 输出路径。

调用者 `0x500269` 的基址为 `设备容量字节 × 128 × 配置索引`。该设备容量字节位于设备信息结构的第 6 字节；目标键盘读取值为 24，对应候选宏区容量 3072 字节。这里的配置索引含义仍需继续确认，不能直接据此写入。

## 候选数据结构

序列化函数先收集绑定到物理键的宏动作，`ActionType = 2` 进入宏路径。

| 区域 | 静态分析观察 |
| --- | --- |
| 0–1 | 小端 55AA，即字节 AA 55 |
| 2–3 | 本次序列化数据总长度，小端 |
| 4–5 | 收集到的宏数量，小端 |
| 前 16 字节其余部分 | 尚未确定，不能假定为零 |
| 16 起 | 每个宏的两字节偏移表 |
| 每宏数据头 | 事件数量小端两字节，指针再推进 4 字节；剩余两字节尚未确定 |
| 每事件 | 4 字节，来源为 ActionMacroEvents |

事件转换函数 `0x480B80` 从官方 JSON 的 `Delay`、`Type`、`Button`、`Action` 生成如下四字节记录：

| 字节 | 含义 |
| --- | --- |
| 0、1 | Delay 的小端整数 |
| 2 | Type；Action 等于 down 时设置最高位 80 |
| 3 | Button 的低字节 |

普通键、修饰键及鼠标事件的 Type 取值仍未完成对应验证。延迟发生在事件前还是事件后，也不能只凭序列化代码定论。

## 当前实现与下一步

应用已有宏编辑、按下/松开平衡检查和配置导入导出。尚未把上述候选协议接入写入按钮。

还需要确认完整头部、类型编码、绑定记录及宏区读取/恢复办法；再做受控的短宏测试与断电保存验证。仅发现写入命令不足以提供可恢复的宏配置功能。本轮未向键盘发送 15、95 或猜测的宏读取命令。
