## 保存路径与空宏的新增证据（工具 v62）

步骤操作后，wrapper 0x4b3400 进入目标设备 0x512770，先通过 0x452f60／0x452f90／0x453030 同步当前事件列表，再复制控件 +0x928 值到原动作的 ActionContent.ActionMacroEvents，按已有动作索引更新主机配置。目标虚函数 +0x300 指向 0x4fb2f0，并转发到 device+0x4000 的 vtable+4；本次没有据此推断嵌套实现是 USB 或落盘。

原事件值由类型 0 构造；循环内按下标写事件时才转为类型 6。零步骤跳过循环直接保存原值，JSON writer 的类型 0 分支输出 null。因此官方零步骤路径不能一概称为保存空数组 []。工具固定九段方法、十三处指令、JSON writer／size 两项分派表、三个 ASCII 字段及目标虚函数，真实官方文件只读核对通过。

目标宏发送器 0x4fff96 取事件数量时，null 的 size 分支返回 0，随后写入零事件数量并跳过事件循环。这与“没有任何宏绑定则不发送银行”不同：仍绑定的零事件宏不能被当成解除所有绑定或银行擦除。

已确认的产品缺口：两端宏导入和验证拒绝 null／空步骤，包含未绑定空宏的官方草稿也可能被整份拒绝；目前步骤清空只处理编辑草稿。需要补齐主机草稿／导入导出兼容，同时区分空绑定、零事件记录和正常事件宏。零事件在固件中的执行／停止行为与嵌套主机保存实现仍待继续静态核对；本次不放宽硬件发送权限，也不把编译或 JSON 保存当作实机通过。


## 空宏数据兼容接入（2026-10-07）

两端宏模型和银行解析／编码现接受零事件记录，保留其名称、播放方式、来源索引、保留字节及绑定；没有绑定与有零事件记录继续区分。官方导入接受显式 null 或数组，字段缺失／错误类型仍拒绝；导出保留原空宏的 null／[] 形式，从非空步骤清空或新空宏按具名官方路径输出 null。未知事件附加字段无法对应时继续拒绝无损导出，不在清空时丢弃。

原生／网页编辑区允许保存清空后的宏，保存不自动解除绑定。纯事件观察器明确拒绝为无输出宏生成执行通过结果，避免零步数取模以及等待后伪通过。录制仍须至少一个实际操作才能采用，空宏使用手工清空／保存。

固件工具 v19 定位 0x2f780 的宏计数与读取路径：0x2f826..0x2f834 从银行偏移表读记录，再加载事件数量；零数量在 0x2f7a0 跳转 0x2f7fc，绕过四字节事件读取消费。固定两个代码片段、四处指令及银行 literal；TBB 表数据明确排除。完成／重启的其他分支、运行固件身份及实际停止行为仍待进一步核对和最终实机验收，不据此宣称空宏实机通过。

## 鼠标位移步骤（2026-10-08）

客户端“编辑宏步骤”中可添加 X／Y 位移；网页版在添加事件中选择对应轴，再编辑位移数值。每次添加一个事件，可复制、排序、删除并设置事件后的等待。范围为 -256…255 的有符号设备单位，不是屏幕像素；负数表示反向。位移没有按下／松开配对，不占用按住状态。两端配置和 Windows JSON 保存原始方向位及数值字节，负向零字节正确表示 -256。

这项依据固定官方构造器及 0104 固件静态派发接入；本型号 Windows 界面是否显示轴控件、当前键盘固件身份、实际位移和断电保留尚未确认。录制器不把屏幕坐标转换成设备位移，不自动录制运动。滚轮及其他扩展事件尚未确认，继续拒绝转换并保留原始备份。

当前按键执行观察器不能判定位移宏通过。网页版停止观察会将页面内指针移动计入活动，重新计算静默间隔；仍须用户明确确认已经停止，不证明页面外或固件内部停止。原生停止观察遇到未支持的位移报告会中止，不忽略它并继续发送。所有真机验收后置。


## 本机宏编辑草稿保存（2026-10-08）

保存宏以及宏库复制、删除、清空、分配、解绑和扩展格式转换，会保存一份最新的本机编辑草稿；未点击保存的步骤输入不会自动保存。Mac 在“宏草稿选项…”中载入，网页点击“载入上次宏草稿”。载入前会提示替换完整编辑区，包括保存时的键位、灯效和文本定义；不会自动写入键盘。草稿与硬件读回名称资料分别保存，读取键盘不会自动采用旧草稿。本机草稿只保留最新一份，重要版本请导出 JSON；清除浏览器网站数据会删除网页草稿。保存失败会明确提示。

官方步骤回调 `0x5129e8` 的 +0x300 进入 `0x4fb2f0`。构造器 `0x4f6131..0x4f6137` 在 device+0x4000 初始化 `CKeyboardProfiledata`，`0x482e22` 设置 vtable `0x77d174`；+4 到 `0x47cac0`，+8 到 `0x47c9a0`，最终进入既有 `profileFileStorage` 已核对的 JSON 文件保存路径。工具 v63 将这条宏回调与文件存储证据接合；这不是 USB 宏区发送或断电保存证明。

此前仅在编辑内容与读回完全匹配时保存名称资料，绑定宏的未写入修改可能在退出／刷新后丢失。本次分别接入本机草稿写入／读回核对及显式载入，保存时保留完整配置来源；不把它作为当前硬件基线。Mac 移动重叠的扩展按钮到宏草稿选项菜单。只完成源码、语法和编译审查，退出／刷新后的载入行为尚待最终统一验收。


## 删除和解绑后的按键功能（2026-10-08）

Mac 删除、清空宏库或解除所选键绑定时，可选择恢复默认功能、禁用或取消；无绑定的宏库删除直接处理库。网页版先在宏页“删除／解绑后的按键”中选择禁用或恢复默认，再执行相应操作。恢复默认只采用配置内完整默认表中可识别的普通键／媒体键记录，未知默认记录不猜测、不降级为禁用；写入前映射须与最近实际读取一致。单独解绑保留宏库；删除宏不删除其他宏。操作仍只修改编辑区和最新本机草稿，需另行写入。

官方依据为 `defaultKeyActionBranch` 的 `0x4ff07d` 默认表复制及 `0x4ff0fd -> 0x4ff515` 零 ActionLink 跳过动作编码路径。恢复默认对应取消动作引用保留默认记录，不把 CherryMac 新增的宏库清空按钮等同于官方事件列表清空。官方布局没有绑定时仍不发送新宏银行；宏尾部和零事件记录的区别保留。不能据此宣称全程序或固件会擦除宏区。

Mac 容量摘要改为名称下方独立单行，详细信息可点击“宏容量详情…”查看，也可通过摘要悬停和辅助说明读取；右侧按键、间隔输入不再与摘要重叠。本轮只核对源码、编译与交付，不运行界面／行为或真机测试。恢复默认后的实体输出、未知默认值拒绝和两端联合使用留到统一验收。


## 解绑结果贯通写入计划（2026-10-08）

组合审查发现，0.55.0／Web 0.54.0 的编辑区支持恢复默认，但官方布局以实际读回作为起点生成计划时，会把已解除的原宏键重新设为禁用。本次为官方草稿记录增加可选 removedKeyAssignments，记录用户选择的最终普通／媒体键功能，并贯通计划、读回核对与本机名称记录。覆盖项只允许作用于起点中确为宏、当前已无绑定的可配置位置；禁止普通键、内部键、重新绑定的键或未知类型借此进入宏发送范围。起点保留真实读回，不修改原备份。

缺少新字段的旧记录仍按原禁用语义重建，空覆盖表不输出；新记录的对应关系会重新计算并核对。原始宏尾部、无绑定不发新银行和普通键／灯效草稿隔离保持。修正只经过源码审查与编译、包内容核对，尚未启动行为或真机测试。


下述是 v64 核对前的审查记录，最新结论与实现以末尾“解绑结果的 Windows 官方动作导出”为准：核对官方 JSON 中解绑后普通／媒体记录的导出与重导入，特别是 Assignment、DefaultAssignment、ActionLink=0 及动作引用的适用来源。已定位两端导出普通记录会设置 Assignment 并取消动作引用，需结合官方发送器起点 +0x2730 的填充来源核对实际语义，暂不凭零引用分支就断言 Windows 会忽略导出配置。该项尚未完成，不启动官方软件或设备试验。


## 解绑结果的 Windows 官方动作导出（2026-10-08）

官方具名初始化路径 `0x4fc28c -> 0x4dc2d0` 读取默认表，`0x4fc297..0x4fc2a8` 复制到 +0x2730；常规读取命令 7，transport+0x44 的 word 等于 1 时选 0x87。键位发送器先复制此表，ActionLink=0 跳过动作编码，因此修改 Assignment 并取消引用不能在此路径编码非默认键。Type 1 读取 ActionContent.ActionKey，将非零数值逐字节写入；禁用值 0x200000 也是非零。工具 v64 固定这些指令并保留初始化／发送范围限制，不宣称全程序别名或实际执行已验证。
