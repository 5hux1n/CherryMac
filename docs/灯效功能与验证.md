# 灯效功能与验证

CherryMac 0.6 提供逐键静态配色，以及键盘固件内置的灯效模式。写入目前使用 USB 有线连接。

## 可以调整什么

- 单个按键：颜色面板、RGB 数值、HEX 色号、RGB 颜色强度与熄灭。
- 多个按键：⌘点击、多选开关、全部按键及常用区域选择。
- 批量配色：横向／纵向渐变、静态彩虹、皮卡丘和喷火龙配色；之后仍可修改任意单键。
- 全局模式：12 种官方可见模式，亮度 0–4、速度 0–4、方向及单色／彩虹参数。个别模式可能忽略不适用的选项。

颜色强度通过缩放 RGB 实现，不是独立的逐键硬件亮度通道。颜色为黑色时没有可保留的色相，提高强度会得到灰色；需要恢复原色时重新选色。渐变按所选按键的中心位置插值，未选中的键和隐藏固件位置保持原颜色。

逐键动画、逐键速度和动态灯效叠加尚无已验证协议，当前不提供。键盘图显示静态配色；内置动画在写入后由实体键盘执行。

## 模式来源

模式名称和编码来自用户提供的 Windows 官方程序中的 Pokémon 对应默认灯效表及模式序列化逻辑。只提取协议事实，没有在本仓库包含官方程序、界面图片或其他官方资源。

| 模式 | USB 模式值 |
| --- | --- |
| 波纹 | 0 |
| 光谱 | 1 |
| 呼吸 | 2 |
| 常亮 | 3 |
| 自定义逐键颜色 | 8 |
| 霓虹 | 10 |
| 曲线 | 12 |
| 折返 | 15 |
| 放射 | 18 |
| 扩散 | 19 |
| 单点亮 | 21 |
| 闪电 | 23 |

官方 JSON 中的 `SelectItem` 是列表索引，不能直接当作 USB 模式值。列表还包含隐藏项，序列化会查表转换。此前仅凭键盘当前值 23 推断自定义模式并不可靠；0.6 使用官方表中的自定义值 8，并保留未知／原有模式的选择项。

参数前九字节分别为配置索引、模式、亮度、原始速度、方向、彩虹选项、R、G、B。界面速度从慢到快递增，原始速度为 `4 − 界面速度`。方向和颜色选项默认保留原值，仅显式选择时改变；彩虹选择写 1，单色写 0。其余参数字节保留。

## USB 实测结果

设备为本机 `046A:01CE`。只读查询的 126 个 LED 索引中，键盘图对应的 109 个实体键位均有有效索引。使用与应用相同的写入方法，先完整读取和备份键位、56 字节灯效参数、126 个 RGB 和 3071 字节宏区；每个写入或恢复包前检查全部按键与修饰键连续松开。

1. 计算器键写入 RGB `(7,123,249)`，W 键写入 `(255,214,0)`，模式设为 8。完整读回一致，键位与宏区未变，随后完整恢复原配置。
2. 其他 11 个模式逐项写入并完整读回；每次测试后恢复原配置。
3. 测试常亮、亮度 3、最快速度、反向、统一单色 RGB，以及波纹和彩虹选项 1。参数读回一致，测试后恢复。
4. 最后再次完整读取，灯效参数、全部 RGB、键位与宏区均与测试前一致。

这些结果确认命令被接受并可读回，**不能代替实际动画外观的观察，也不能证明断电保存**。还需要用户核对逐键颜色对应的实体位置、各模式的视觉效果、切换连接后的保留及断电持久化。

离线测试覆盖严格颜色解析、颜色强度、单键与区域配色、物理位置渐变、隐藏位置保留、无效输入不改配置，以及编辑不改变设备基线。模拟固件测试继续检查写入失败恢复、基线变化、备份失败与按键按住时中止。

## 2026-10-04：两端编辑区写入计划核对

客户端与网页灯效页新增“核对灯效写入”。先读取完整配置，导入本型号官方 JSON，将修改保存到编辑区，再核对或导出 JSON。核对显示模式、亮度、颜色变化位置数与参数是否改变；文件附带原配置、预计读回及候选指令顺序。核对本身不访问设备、不写入、不授予写入权限，正常预览的灯效写入仍关闭。

逐键核对要求有效 LED 映射与官方原始 RGB 来源。硬件读回 RGB 已处理亮度，官方原始 RGB 则需按官方算法处理；便携配置新增可选 `lightingColorEncoding` 区分两者。来源未知的旧文件和直接读回颜色不能进入逐键候选计划，需重新导入官方配色，避免再次缩放亮度。重新读回会重置来源，宏恢复保留灯效草稿时也保留来源。内置模式核对不要求逐键颜色表。此约束最初只适用于写入计划核对，随后已接入两端产品的 Windows 配置草稿导出及文件转换命令。

验证仅使用文件与内存：两端候选计划及目标一致，255/128/1 在亮度 2 时仅转换一次为 134/67/0；按键及宏严格沿用基线，拒绝未知或无效颜色来源，保留输入文件，并验证来源元数据往返。客户端产品编译、网页脚本及 PHP 语法检查通过。没有连接或修改键盘；这不构成灯效颜色或断电保留的真机验收。

### 官方草稿导出统一颜色来源校验

两端产品新增配置级导出入口，灯效核对与完整 Windows 草稿导出共用它。自定义模式必须使用明确标记的官方原始 RGB，否则拒绝导出；内置模式遇到读回或来源未知的 RGB，只更新有效灯效参数，完整保留官方模板中的逐键配色，并提示用户。已有原始 RGB 的草稿仍合并逐键编辑。内置模式模板不含逐键颜色表时也能导出。底层快照转换仍供受控离线研究使用，不直接接到产品导出按钮。文件命令禁止覆盖输入配置及模板。

这修正了产品导出可能将已缩放颜色误当作原始颜色的问题；不证明它是先前实体故障的根因，也不恢复无法唯一反推的原始颜色。

本次增量的必要检查直接使用打包后 App 的纯文件命令与网页函数：官方原始配色导出、没有逐键表的内置模式、读回 RGB 保留官方表三类结果一致；拒绝来源未知的自定义配色与非法参数；禁止覆盖配置或模板。App 0.24.0 build 26／PHP 0.18.0 已生成独立包，先前包保留。编译与语法检查通过；未访问硬件、启动产品界面或申请权限。

## 2026-10-05：从恢复记录导出原始恢复计划

两端“检查灯效恢复记录”接入恢复计划导出。原生分析后可选择导出分析或恢复计划；网页检查通过后启用“导出恢复计划（未执行）”。新文件不修改编辑区或访问设备，也不是发送授权。缺少完整读回、存在范围外改动或不是已核对分块前缀的记录拒绝准备。状态已与原备份一致时，生成零报告计划，不能由此断言闪存提交或断电持久化。

原始写入记录按保存的当前快照生成恢复计划；恢复中断记录经重新核对后导出原恢复计划，保留原始开始状态及原备份，允许后续执行器从已核对恢复前缀重新读取和验证。不会把恢复中的混合前缀冒充原写入前缀。计划据保存记录准备，不能当作当前实体状态；实际恢复前须重新读取完整配置。恢复报告保留原始 RGB 与参数值，绝不进行亮度缩放。

新增纯文件函数及原生 --export-lighting-restore-plan INPUT OUTPUT。必要检查覆盖原写入、恢复中断、已经一致三类两端计划一致性；缺失或未知状态拒绝、源记录不变及输入文件保护通过。产品编译、JavaScript 与 PHP 语法检查通过，没有设备、权限或界面启动。更新独立预览版本为 App 0.26.0 build 28／PHP 0.20.0，灯效真实写入／恢复仍关闭。


## 2026-10-05：独立网页灯效验收入口

新增 Web/lighting-test.php，默认返回 403；只有部署者明确设置 CHERRY_LIGHTING_TEST=1 才显示独立研究页面。普通配置页面、现有 PHP ZIP 的运行文件白名单及 Mac 预览包不启用或收录该入口。没有启动本机服务、浏览器、权限申请或键盘测试；灯效实物验证仍遵循用户暂缓统一测试的安排。

入口按四步组织：载入主页面导出的灯效核对文件或既有写入／恢复记录；选择并读取 USB；显式确认后备份并发送；断电重连读回及恢复、下载资料。载入写入计划重新生成目标并比较完整配置，随后按既有指定固件／bank 0／selector 0／cap 56／完整 begin 约束核对。写前使用完整原始基线，底层执行器两次重新读取，备份与操作记录持久保存后才发送。取消只停止后续报告，不能撤回已发报告，不自动重试。

本地数据库保存备份、逐包 USB 请求／回复、独立恢复记录和本轮资料。下载本轮资料与独立恢复记录使用两个明确按钮，避免浏览器拦截第二个自动下载。恢复记录可在新会话单独载入；缺少历史最终读回时，会用新读取的当前配置重新检查前向／恢复分块范围，而非据缺失日志推断设备没有改变。恢复中断继续沿用原计划及原始颜色字节，不再缩放。未知或范围外变化拒绝。

断电步骤记录 USB disconnect 事件及用户关电确认，再要求观察到至少 15 秒后的 USB connect 事件，重新选择设备后完整读回。单纯关闭浏览器 USB 会话不视为物理拔出，过早重连拒绝作为本轮断电证据。浏览器无法证明电池已关电，结果只表示用户确认后的重连读回；灯光外观和真实持久性仍须统一实体验收。更换设备身份的实机核对也不能由文件或相同 VID/PID 替代。

新增 lighting-test-plan.test.mjs，只在内存核对篡改目标拒绝、缺少历史读回时的新读回恢复、原始／中断恢复计划保留和范围外变化拒绝；通过 JavaScript／PHP 语法、默认关闭路由和正常运行白名单检查。不把这些检查视为界面实际运行或固件验收。下一步补齐客户端对应验收流程，再按用户安排统一实机核对；本次没有更新现有 App 0.26／PHP 0.20 包。


## 2026-10-05：客户端独立灯效验收窗口

客户端在 CHERRY_LIGHTING_TEST 研究编译条件下新增“独立灯效验收”窗口，入口位于灯效页；普通产品编译不显示或包含该窗口。打开窗口只展示操作，不连接设备或申请权限；点击“读取 USB 配置”才创建连接监测及只读会话。测试期间主配置窗口暂停其他操作、停止文本服务；验收窗口与主窗口使用相同串行队列，等待文本服务释放后才读写。关闭后要求主页面重新读取配置，不沿用旧基线。

可载入灯效写入核对文件、写入记录或恢复中断记录。写入文件重新生成预计目标并核对完整快照，随后按已有指定固件／bank 0／selector 0／cap 56／完整 begin 规则校验。确认后调用现有研究执行器，写前备份并核对备份读回，每个阶段保存兼容网页的独立恢复记录；原始 USB 请求／回复和完整快照保存在同一资料目录。原始数据恢复先新读回，再检查整块前缀与范围，缺少历史读回也不推断状态未变。恢复中断保留原计划与原 RGB，不再次降低亮度。

运行时提供停止后续发送，窗口失去前台也请求取消。底层研究灯效接口增加可选操作日志：等待按键释放前后，以及保存 OUT 日志后、发送前检查取消和日志健康。记录持久保存另用不因用户取消而拒绝保存的存储健康检查，以保留取消后的读回与失败记录；日志磁盘失败仍拒绝继续发送。已在途报告不能撤回，失败不自动重试。

USB 监测按 registry ID 记录移除、用户关电确认及新设备重连，要求确认到重连至少 15 秒；完整重连快照与预计目标核对。记录只能证明操作系统事件和用户确认，不能证明电池实际关电、视觉灯效正确或所有固件持久性。资料包括 power-events.json、每次操作日志、原始备份、完整读取快照和独立恢复记录，可通过窗口打开资料目录，无需手工抓包。

新增纯文件命令 --prepare-lighting-recovery RECORD CURRENT OUTPUT，与网页 fresh-read 函数生成相同恢复计划，拒绝覆盖任一输入文件。研究版与普通产品源码编译通过；针对文件检查通过缺少历史读回、恢复中断、原状态无报告、未知变化拒绝及输入保护。没有启动 App、打开浏览器、运行服务器、查询权限或访问键盘。现有 App 0.26／PHP 0.20 包不替换，本轮新研究界面的实际交互、固件回复、断电保存与灯光外观仍待统一真机验收。
