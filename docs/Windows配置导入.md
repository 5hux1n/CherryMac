# Windows 官方配置导入

CherryMac 0.7 支持用户提供的 Pokémon 型号 47 的 Windows JSON。需先读取当前 USB 键盘，再导入到编辑区；导入不会自动写入硬件。

## 转换依据

官方文件有 126 个逻辑条目，排列按键盘行；本机 USB 表则使用固件矩阵顺序。导入器核对型号标记与完整 `DefaultAssignment` 布局，再按实体键的固定身份映射到矩阵位置。颜色采用同样的转换；官方颜色发送路径也使用键位索引向量。

例如，Windows 逻辑条目 17 是计算器，USB 矩阵位置是 102。直接把逻辑条目 17 写到 USB 位置 17，会错误地影响左 Alt。已有自定义映射不能作为识别物理位置的依据。

普通 `Assignment` 和 `ActionKey` 的三字节记录来自整数的高、中、低字节。`ActionLink` 非零时查 `ActionInfo[ActionLinkIndex]`，未绑定的动作库不应用。`ActionMedia` 是官方媒体表的索引，需要转换为相应 Consumer Usage，不能当成原始 Usage。

`SelectItem` 是包含隐藏项的官方模式表索引。逐键颜色的列表索引为 21，对应 USB 模式 8；用户提供的 `SelectItem = 8` 对应模式 10。亮度原样转换，速度写为 `4 − Speed`。导入只更新已知灯效参数，保留第九字节之后的参数与系统设置。

单次键盘宏按 `ActionMacroEvents` 转换。普通键 Type 10 使用 HID Usage；Type 9 修饰键的 Button 是位掩码。只接受逐步延迟、执行一次、按下与松开平衡的键盘宏。相同动作被多个实体键引用时共享一个导入宏，重名时添加后缀。已有宏库保留，原有实体绑定按导入配置替换；容量检查失败则整个导入失败。

## 保留和拒绝规则

- 107 个可改实体键可以导入功能；Fn 与 CHERRY 两个内部键保留当前功能。
- 109 个实体键可以导入颜色；17 个隐藏／额外布局位置保留原颜色。
- 未知参数、系统参数、未改动的宏原始区不重新编码。
- 布局不一致、损坏引用、不支持的灯效、文本／其他动作、鼠标／滚动宏、循环／切换宏、固定间隔宏、无法解码的原宏或容量不足，会拒绝整个导入。
- 导入失败不改变当前编辑区和设备基线。输出为 CherryMac JSON，暂不输出官方 Windows 格式。

## 验证

合成离线样例覆盖计算器位置、109 色映射、隐藏位置保留、快捷键、媒体索引、修饰键宏、错误型号与布局、无设备基线及无效输入不改变编辑区。

用户提供的真实文件已离线转换：107 个可改键、109 个颜色、0 个绑定宏。转换后的键位与原 USB 读取表一致，原宏区逐字节保留，未知灯效参数不变，灯效列表索引 8 转换为模式 10。这不是硬件写入测试；没有将该用户文件或转换结果上传到仓库。
