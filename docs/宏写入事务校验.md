# 宏写入与恢复范围

本页记录源码中的离线实现，不表示宏已开放写入或通过真机验收。当前顺序是完成宏模块，随后进行真机写入、执行和断电测试，通过后再推进灯效。

## 本次补齐

客户端与网页版增加同样的宏事务计划。计划复制并保存读取时的完整配置、目标宏区与键位，以及临时禁用宏触发键的状态；不依赖后续修改的编辑草稿。

- 只接受当前已识别固件的完整配置，设备信息、参数与颜色保持原值。
- 只允许宏绑定变化及移除宏后的普通／媒体键恢复；不能夹带其他普通键修改，不能修改内部或隐藏位置。
- 宏事件仍须按下／松开配对、索引有效且满足容量限制。
- 每个写包必须完整匹配本次原值、目标值或临时禁用键位。宏区只允许发送实际变化的 54 字节分块，末块最多 47 字节，恢复也遵守相同范围。
- 恢复前重新读取完整配置。键位逐块必须属于本次允许状态；宏区的每一块，包括本次未修改的块，必须属于原值或目标值。出现其他数据或灯效／设备变化就停止自动覆盖并保留备份。

客户端已有模拟宏写入器使用此校验，维持事件区先写、偏移 0 的头部最后写、暂时禁用触发键、等待有限宏结束、完整读回及范围内恢复。网页版已增加使用该计划的联合写入事务，并以模拟传输验证；实际 CherryHID 尚未提供宏授权入口，不能向实体键盘写入。两端正常产品入口仍阻止宏与灯效写入。

## 验证范围

原生自测覆盖原值／目标／临时禁用包、部分宏块写入、不同字段的范围外变化、篡改包、未改变宏块、隐藏绑定、夹带普通键、原媒体绑定恢复及宏触发键迁移。模拟固件额外覆盖“写入已执行但回复丢失，同时参数发生额外变化”：停止恢复，不继续发包覆盖该变化。

网页核心测试覆盖相同的计划范围、输入与返回值的独立复制、部分写入、非法绑定和恢复原媒体键。测试不打开实际 USB，不计入真机验收。

## 宏模块仍待完成

当前写入计划与原生模拟写入器支持指定次数 1–255，并按绑定的实际事件延迟与次数计算名义等待时长。即使仅更改绑定次数，也先禁用原触发键并等待；恢复同样考虑原值与目标的次数。未绑定宏不计入等待。这是软件预算，不是固件已停止的证明，实际延迟、并发／排队、次数与结束行为仍需真机确认。按住持续和再次按键停止已支持导入与编辑，其写入过程所需的停止／中止与恢复语义尚未完成。官方滚轮、文本动作及本型号可用性仍需核对；网页宏传输授权、逐包等待、可靠日志与恢复还需接入。完成这些代码和审查后，才启动用户已授权的真机宏测试和断电保留测试，日志自动保存。

## 2026-10-03 持续／开关的停止事务

两端事务计划把指定次数的名义等待和持续／开关的停止要求分开。默认构造仍拒绝持续／开关；只有测试调用明确提供停止处理器时，才允许规划这些执行方式。停止处理器收到完整配置、涉及的触发键、执行方式、事件和静默观察预算；这份请求本身不证明宏已经停止。

修改原持续宏时，**先停止、再禁用触发键**，保留再次按键停止所需的原触发功能。处理器失败或返回后配置改变，均不发送写包。失败恢复前同样先读取并核对范围，处理新旧配置中可能存在的持续宏；停止失败不发送恢复包，不能靠有限毫秒等待替代停止。停止期间可能发生配置变化，因此恢复还会再次读取并校验范围。

研究程序增加 `MacroPhysicalStopController` 原生窗口，供硬件队列中的停止处理器调用。窗口只观察唯一 USB 目标键盘，提示用户停止已经运行的宏，等待按键／鼠标释放及按事件周期计算的静默窗口，随后接受无修饰键的鼠标确认。确认后继续观察至少 250 毫秒；这把键盘的新输出、失焦、断开、未知输出、取消或日志失败阻止继续。多项触发键说明可滚动查看。每次保存 `request.json` 和 `stop.json`，明确标注用户确认与观察范围，不声称测量了固件内部停止或电池断电。

窗口仅在研究编译中存在，尚未接入完整宏产品／验收入口，当前没有开启实体宏写入。若无法确认停止，取消、关闭键盘电源，重新连接读取；原会话不会继续发送。重新连接后的恢复串接及网页停止窗口仍需完成。

原生 17 组检查及采集／停止窗口离线检查通过；网页核心 42 项通过，覆盖两种持续方式的停止顺序、拒绝停止、停止期间配置改变、新旧候选的恢复停止要求及拒绝时没有恢复包。原生窗口离线渲染检查通过，没有打开 IOHID 管理器。本阶段不作为实体停止语义、实际执行或断电保留验收。


### 2026-10-05：宏恢复保留其他编辑草稿

审查发现恢复合并函数只保留参数、颜色与普通键草稿，没有保留当前 LED 映射、便携文本草稿和官方模板，可能让逐键配色和官方导出丢失上下文。两端现在同时保留这些资料及官方模板的未知字段、设备设置草稿。恢复宏仍采用原宏库及绑定；如果原宏携带官方动作来源，则在当前模板中复用或追加完整的原动作，再重映射来源索引，避免模板动作顺序改变后指向文本或其他宏。重复恢复复用已存在动作，不持续追加重复资料。当前已清除的 LED／文本上下文不会从旧资料重新出现。

无效动作列表拒绝合并。硬件恢复成功但编辑区合并失败时，客户端保留原编辑区并明确报告两者状态；不再静默丢弃草稿并宣称保留成功。网页相同失败保留原编辑区，并要求重新读取。合并不安装文本服务、不写灯效或设备设置。

新增必要的纯内存检查覆盖当前官方未知字段与回报率草稿、LED／文本资料、原宏动作额外字段、来源索引重排、重复恢复与输入不可变，以及无效列表拒绝。原生检查入口 --macro-recovery-draft-self-test 位于 GUI／HID 启动前；网页版测试文件 macro-recovery-drafts.test.mjs 不调用浏览器。实际宏／灯效统一验收继续暂缓。
