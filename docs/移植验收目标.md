## 推进顺序

1. **按键产品化**：将目前受限研究程序的已验证写入路径接入客户端与网页。点选按键、编辑、显示变更、自动备份、确认释放、逐包写入、完整读回和恢复形成可用流程；默认只处理键位表，禁止顺带重发灯效或宏。故障与恢复状态必须直接显示给用户。
2. **按键验收与持久化**：从已有计算器结果扩展到普通键、组合键、媒体键、禁用和还原；验证修饰键正常释放、断电／重连保留与 Mac 端快捷操作。对无线保留和无线写入分别记录证据，不将其中一种推定为另一种。
3. **官方功能对照**：以本型号在 Windows Utility 中实际可见的功能建立对照，核对 JSON、型号分支和通信协议。完善宏、灯效与设备设置的两端实现及离线校验；宏代码完成后进行用户已授权的真机与断电验收；灯效在宏验收后推进。未知或不支持的项目需要明确说明，不能伪装成已支持。
4. **恢复与诊断**：官方 JSON 和 CherryMac 备份导入、未知数据保留、写入失败中止、恢复旧配置、断线重连与日志自动保存。避免要求用户手工抓包或搬运日志；确实缺少证据时给出最少必要操作。
5. **两端交付**：核对功能一致性和界面可用性，自行审查代码，完成有意义的检查，生成可直接打开的 `.app` 和 PHP ZIP、校验值与使用说明。按真实功能状态发布，不覆盖旧版本发布资产，不收录用户原始配置和日志。

每轮应推进下一个实际实现或解决一个明确阻碍。进度说明报告已完成什么、哪些证据仍缺失以及正在推进什么；用户无需每次测试后再说“继续”。
