用户于 2026-10-02 明确要求：针对 CHERRY MX 3.0S Pokémon Wireless，逆向其 Windows 官方配置软件，复刻功能至 Mac 客户端和无需构建的 PHP 网页版；实现后自行核对、校验、审查代码，再打包交付。客户端和网页按功能分页面，保持简单易用。

## 持续工作目标

2026-10-02 用户再次明确：交付成品，完整复刻该型号 Windows 官方配置功能，构建 macOS 客户端和无需构建的 PHP 网页版。单次按键验证只是进度节点，不作为结束条件。

持续目标：基于已经取得的官方安装包、型号资源、导出配置、开源实现、现有代码与真实 USB 日志，逐项确认该型号的协议和行为，完成两端功能、代码审查、有效测试、打包发布和面向用户的说明，直至以下交付标准全部满足。当前顺序：完成宏模块代码与离线校验，再进行宏真机写入、执行和断电保留测试；宏验收后再推进灯效模块。按键流程继续维护，宏缺项阶段不提前写入。

仅在需要用户实体操作、缺少决定实现的关键资料或遇到系统硬限制时等待对应步骤。等待某一项时继续推进不依赖它的实现、审查、测试和文档。不能用报告、预览版、模拟测试、单个实体键成功或打包成功替代完整验收。已完成的试验不要求用户重复，现有配置、日志与协议结论继续复用。

## 推进顺序

1. **按键产品化**：将目前受限研究程序的已验证写入路径接入客户端与网页。点选按键、编辑、显示变更、自动备份、确认释放、逐包写入、完整读回和恢复形成可用流程；默认只处理键位表，禁止顺带重发灯效或宏。故障与恢复状态必须直接显示给用户。
2. **按键验收与持久化**：从已有计算器结果扩展到普通键、组合键、媒体键、禁用和还原；验证修饰键正常释放、断电／重连保留与 Mac 端快捷操作。对无线保留和无线写入分别记录证据，不将其中一种推定为另一种。
3. **官方功能对照**：以本型号在 Windows Utility 中实际可见的功能建立对照，核对 JSON、型号分支和通信协议。完善宏、灯效与设备设置的两端实现及离线校验；宏代码完成后进行用户已授权的真机与断电验收；灯效在宏验收后推进。未知或不支持的项目需要明确说明，不能伪装成已支持。
4. **恢复与诊断**：官方 JSON 和 CherryMac 备份导入、未知数据保留、写入失败中止、恢复旧配置、断线重连与日志自动保存。避免要求用户手工抓包或搬运日志；确实缺少证据时给出最少必要操作。
5. **两端交付**：核对功能一致性和界面可用性，自行审查代码，完成有意义的检查，生成可直接打开的 `.app` 和 PHP ZIP、校验值与使用说明。按真实功能状态发布，不覆盖旧版本发布资产，不收录用户原始配置和日志。

每轮应推进下一个实际实现或解决一个明确阻碍。进度说明报告已完成什么、哪些证据仍缺失以及正在推进什么；用户无需每次测试后再说“继续”。

## 界面与交付

- 客户端与网页使用一致的功能导航：键位、灯效、宏、配置与备份、设备与诊断。
- 灯效拆分为内置模式和逐键配色，RGB 与其他精细选项按需要展开。
- 配置与诊断页面无需重复展示完整键盘；编辑页面保留按键上下文，切换页面保留草稿。
- 正常单键保持正方形，右上角计算器与三个媒体键位置正确；检查窄窗口、深色和键盘导航。
- 代码审查需核对型号分支、参数边界、隐藏数据、故障中止与恢复、隐私和导入兼容；审查结论有可重复的测试支撑。
- 最终交付可直接打开的 `.app` 与 PHP ZIP，并提供一致的版本、校验值、功能状态和使用说明。
- 最终按本型号的官方功能对照逐项验收：两端实现、输入／输出证据、恢复路径及必要的真实使用验证均有记录。任何仍停用、只读、待确认或暂缓实测的核心配置功能都不能计作完整成品。
