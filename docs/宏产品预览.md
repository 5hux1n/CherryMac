# 宏怎么用

当前公开版本为 [Mac 0.87.0](https://github.com/5hux1n/CherryMac/releases/tag/v0.87.0) 和 [PHP 0.86.0](https://github.com/5hux1n/CherryMac/releases/tag/web-v0.86.0)。[在线工具](https://cherrymac.goforit.si/app/) 使用相同网页版本。它们仍是预览版，新版宏存储范围的实体输出与断电保留尚待统一验收。[当前功能状态](当前功能与验收状态.md)

## 编辑与绑定

进入“宏”页面，新建宏，添加或录制按键步骤。支持键盘按键、修饰键和五个鼠标按钮；每个按下都须有对应松开。可调整顺序、等待时间，复制或删除宏。

步骤编辑另提供“复制步骤”和“清空本宏步骤”：复制把包含等待值的副本插入原步骤前；清空只改当前步骤草稿，已保存的宏和绑定保留。Mac 在“编辑步骤”窗口操作，取消可保留原步骤。清空后可添加或录制新步骤，也可保存为空宏；保存不会解除原绑定。空宏没有按键输出，与删除宏或清空宏库不同。删除宏或清空宏库则解除相关绑定，与步骤清空不同。

选择“指定执行次数”“按住持续”或“再次按键停止”，再点击“分配到所选键”。保存宏本身不会改变已有绑定的执行方式。解绑、删除或清空宏库时，可选择恢复关联键的默认功能或禁用；这些操作先修改编辑区，需要另行写入。

单宏最多 762 个事件，总可访问宏区为 3071 字节。容量按实际绑定计算：同一宏绑定多个键会重复占用，未绑定宏只保存本地。旧配置可先点击“启用扩展宏编辑”转换草稿，再核对写入。界面里的等待总量是设置值，不代表实际固件执行时间。

## 录制

选择已保存或导入的宏时，录制界面会恢复它的固定间隔选项及毫秒值。Mac 可在录制窗口点击“采用录制设置”，网页可直接调整选项；然后点击“保存宏”保留设置，不需要重新录制。设置只影响之后的录制，已有步骤的等待时间须在步骤编辑器调整。官方格式没有单独保存“忽略间隔”选项，下次打开恢复为非固定的实际间隔；已录制的零等待步骤仍保留。

开始录制前选择替换、追加或插入位置，以及是否记录鼠标。Mac 另提供其他应用录制，需要对应系统权限；网页只记录当前页面收到的事件。

当前支持五个鼠标按钮。启用鼠标录制时遇到滚轮会取消本次录制并保留原步骤，避免生成尚未确认的事件编码。

## 写入与恢复

通过 USB 数据线连接键盘并切换有线模式，读取当前配置后核对宏变更。宏写入仅处理宏区及相关绑定键，灯效和普通键位草稿分别处理。

操作前保存备份和恢复记录，写入后读回核对。若键盘正在执行连续宏，请先按界面提示停止。点击“停止发送”只停止后续配置写包，不能代替停止正在执行的宏。

断开、取消或写入失败后，在“配置与备份”使用“恢复最近宏写入前配置”。恢复记录包含写前宏名称资料；旧记录或名称资料缺失时仍支持原始硬件数据恢复。不要把导入记录中的读回当作当前键盘状态。

## 保存文件

使用“导出当前配置”保留宏库、绑定和草稿。已导入本型号 Windows 官方模板时，可使用“导出 Windows 配置草稿”；它合并当前键位、宏、文本与灯效草稿，设备设置沿用模板。导入与导出不会自动写入键盘。

网页版数据保存在当前浏览器与网站本地，建议另行导出保存；清理网站数据会删除本地资料。PHP 包无需 Node 或构建，已有 PHP 时解压并运行 start.command。具体启动及包校验见[公开预览版发布](公开预览版发布.md)。

追加或插入录制时，窗口会显示扣除原步骤后的可录制事件数；空间不足时先删除步骤或改为替换全部。旧共享宏格式最多 256 个事件，启用扩展宏编辑后最多 762 个事件。手动添加、步骤编辑和录制采用同一限制，完整宏库仍受 3071 字节的总容量限制。

官方空宏可按 `null` 或空数组导入。导出保留原模板中的空值形式，新建或从非空宏清空则使用官方零步骤路径的 `null`。硬件解析／编码保留零事件记录及其绑定，不将它误认为整个宏区清空。新版空宏流程尚待统一实机验收；输入观察不能证明一个无输出宏已经执行。


## 鼠标位移步骤（2026-10-08）

客户端“编辑宏步骤”中可添加 X／Y 位移；网页版在添加事件中选择对应轴，再编辑位移数值。每次添加一个事件，可复制、排序、删除并设置事件后的等待。范围为 -256…255 的有符号设备单位，不是屏幕像素；负数表示反向。位移没有按下／松开配对，不占用按住状态。两端配置和 Windows JSON 保存原始方向位及数值字节，负向零字节正确表示 -256。

这项依据固定官方构造器及 0104 固件静态派发接入；本型号 Windows 界面是否显示轴控件、当前键盘固件身份、实际位移和断电保留尚未确认。录制器不把屏幕坐标转换成设备位移，不自动录制运动。滚轮及其他扩展事件尚未确认，继续拒绝转换并保留原始备份。

当前按键执行观察器不能判定位移宏通过。网页版停止观察会将页面内指针移动计入活动，重新计算静默间隔；仍须用户明确确认已经停止，不证明页面外或固件内部停止。原生停止观察遇到未支持的位移报告会中止，不忽略它并继续发送。所有真机验收后置。


## 本机宏编辑草稿保存（2026-10-08）

保存宏以及宏库复制、删除、清空、分配、解绑和扩展格式转换，会保存一份最新的本机编辑草稿；未点击保存的步骤输入不会自动保存。Mac 在“宏草稿选项…”中载入，网页点击“载入上次宏草稿”。载入前会提示替换完整编辑区，包括保存时的键位、灯效和文本定义；不会自动写入键盘。草稿与硬件读回名称资料分别保存，读取键盘不会自动采用旧草稿。本机草稿只保留最新一份，重要版本请导出 JSON；清除浏览器网站数据会删除网页草稿。保存失败会明确提示。

官方步骤回调 `0x5129e8` 的 +0x300 进入 `0x4fb2f0`。构造器 `0x4f6131..0x4f6137` 在 device+0x4000 初始化 `CKeyboardProfiledata`，`0x482e22` 设置 vtable `0x77d174`；+4 到 `0x47cac0`，+8 到 `0x47c9a0`，最终进入既有 `profileFileStorage` 已核对的 JSON 文件保存路径。工具 v63 将这条宏回调与文件存储证据接合；这不是 USB 宏区发送或断电保存证明。

此前仅在编辑内容与读回完全匹配时保存名称资料，绑定宏的未写入修改可能在退出／刷新后丢失。本次分别接入本机草稿写入／读回核对及显式载入，保存时保留完整配置来源；不把它作为当前硬件基线。Mac 移动重叠的扩展按钮到宏草稿选项菜单。只完成源码、语法和编译审查，退出／刷新后的载入行为尚待最终统一验收。


## 删除和解绑后的按键功能（2026-10-08）

Mac 删除、清空宏库或解除所选键绑定时，可选择恢复默认功能、禁用或取消；无绑定的宏库删除直接处理库。网页版先在宏页“删除／解绑后的按键”中选择禁用或恢复默认，再执行相应操作。恢复默认只采用配置内完整默认表中可识别的普通键／媒体键记录，未知默认记录不猜测、不降级为禁用；写入前映射须与最近实际读取一致。单独解绑保留宏库；删除宏不删除其他宏。操作仍只修改编辑区和最新本机草稿，需另行写入。

官方依据为 `defaultKeyActionBranch` 的 `0x4ff07d` 默认表复制及 `0x4ff0fd -> 0x4ff515` 零 ActionLink 跳过动作编码路径。恢复默认对应取消动作引用保留默认记录，不把 CherryMac 新增的宏库清空按钮等同于官方事件列表清空。官方布局没有绑定时仍不发送新宏银行；宏尾部和零事件记录的区别保留。不能据此宣称全程序或固件会擦除宏区。

Mac 容量摘要改为名称下方独立单行，详细信息可点击“宏容量详情…”查看，也可通过摘要悬停和辅助说明读取；右侧按键、间隔输入不再与摘要重叠。本轮只核对源码、编译与交付，不运行界面／行为或真机测试。恢复默认后的实体输出、未知默认值拒绝和两端联合使用留到统一验收。


## 解绑结果贯通写入计划（2026-10-08）

组合审查发现，0.64.0／Web 0.54.0 的编辑区支持恢复默认，但官方布局以实际读回作为起点生成计划时，会把已解除的原宏键重新设为禁用。本次为官方草稿记录增加可选 removedKeyAssignments，记录用户选择的最终普通／媒体键功能，并贯通计划、读回核对与本机名称记录。覆盖项只允许作用于起点中确为宏、当前已无绑定的可配置位置；禁止普通键、内部键、重新绑定的键或未知类型借此进入宏发送范围。起点保留真实读回，不修改原备份。

缺少新字段的旧记录仍按原禁用语义重建，空覆盖表不输出；新记录的对应关系会重新计算并核对。原始宏尾部、无绑定不发新银行和普通键／灯效草稿隔离保持。修正只经过源码审查与编译、包内容核对，尚未启动行为或真机测试。


## 解绑结果的 Windows 官方动作导出（2026-10-08）

官方具名初始化路径 `0x4fc28c -> 0x4dc2d0` 读取默认表，`0x4fc297..0x4fc2a8` 复制到 +0x2730；常规读取命令 7，transport+0x44 的 word 等于 1 时选 0x87。键位发送器先复制此表，ActionLink=0 跳过动作编码，因此修改 Assignment 并取消引用不能在此路径编码非默认键。Type 1 读取 ActionContent.ActionKey，将非零数值逐字节写入；禁用值 0x200000 也是非零。工具 v64 固定这些指令并保留初始化／发送范围限制，不宣称全程序别名或实际执行已验证。

两端导出现在为非默认普通键、组合键和禁用生成具名 Type 1 动作，已知媒体代码生成 Type 4，未列入媒体索引的原始媒体记录保留为 Type 1 原始字节。优先复用现有相同结果的普通／媒体动作；新增结果也复用引用，避免反复导入导出不断增加动作。原有非宏动作与未知字段保留。只有完整默认映射确认当前记录等于默认时才使用零动作引用；没有映射时导出显式记录，不猜测默认。Assignment 仍保存相同字节，既有 Mac 导入及官方动作导入可取回相同结果；实体 Windows 导入应用行为仍待统一验收。

该修正覆盖宏解绑后结果及合并导出的普通键位，未扩大 USB 写入范围，未运行官方软件、产品窗口或真机测试。


## 官方默认动作导入（2026-10-08）

两端现在接受带动作引用的 ActionType 0：按具名 Windows 发送器 `0x4ff477..0x4ff4b6` 从当前逻辑键的 DefaultAssignment 取三字节记录，不使用可能不同的 Assignment、ActionKey 或 ActionContent。该分支允许 ActionContent 缺失或为空；其他类型仍需合法对象，动作索引、默认值和型号模板继续严格核对。旧的无动作引用文件继续沿用 Assignment 导入兼容行为。

默认动作和宏解绑都只更新编辑区，原始宏区、普通键、灯效与未知模板字段按原流程保留。Type 0 动作源保留在官方模板，后续导出按已确认默认映射选择默认引用或明确记录；没有默认映射时不猜测等价性。USB 写入仍由既有普通键／宏范围验证负责，导入成功不代表允许未知默认键写入，也不代表 Windows 实际应用或实体输出已通过。

## 独立宏步骤文件

独立宏文件：Mac 在“宏草稿选项…”选择导入／导出，网页展开“独立宏文件”。.mac 只保存步骤，导入会确认替换当前步骤编辑区，随后需要点击保存宏；名称、执行方式和绑定保留，不自动写入。支持键盘、修饰键、五鼠标按钮、手动 X／Y 位移及空事件 null／[]；按当前格式限制为 256 或 762 个事件，文件上限 3 MB。带未知附加事件字段的独立文件会明确拒绝；请保留原文件并使用完整官方配置导入，避免丢失来源。由完整配置导出的 .mac 会保留可对应的附加字段，因此这类文件也受上述独立导入限制。
