# 宏基础实机验收

2026-10-03，MX 3.0S POKEMON Wireless 在 macOS USB 有线模式下，通过了计算器键触发「AB 执行两次」宏的写入、实体执行、断电保留及原配置恢复测试。测试使用独立研究 App；普通下载版与网页版尚未开放宏写入。

## 本轮结果

| 检查 | 结果 |
| --- | --- |
| 写入后的完整读回 | 设备信息、键位、参数、颜色、宏区五个区均与目标逐字节一致 |
| 修改范围 | 只有计算器键槽位 102 的绑定改变，原宏库保留并追加测试宏；灯效和设备参数保持原值 |
| 第一次实体输出 | A 按下／松开、B 按下／松开，重复两轮，共八个事件；无残留按住状态或观察中断 |
| 断电流程 | 检测到 USB 断开；用户确认关闭键盘电源，确认到重连约 38.1 秒，超过要求的 15 秒 |
| 重连后的完整读回 | 五个区均与写入目标逐字节一致 |
| 第二次实体输出 | 再次准确输出八个事件，两轮完成，全部释放 |
| 恢复原配置 | 五个区均与最初备份逐字节一致；会话 complete、passed=true，未记录错误 |
| 日志复核 | 两份执行日志的 SHA-256 与评估记录匹配；用产品离线评估入口重放，两份结果均与研究 App 保存的评估完全相同 |

断电证据包含用户确认关闭电池供电的动作，程序没有测量键盘内部电源。本轮证明这把键盘在该操作后保留了测试宏，不把仅拔 USB 当作完整断电。

## 尚待验收

此结果只接受指定的 AB 两次宏，尚不覆盖其他次数、精确延迟、修饰键与鼠标按钮、按住持续、再次按键停止、多触发键并发及中断恢复的所有固件行为。还需验收正常客户端与网页版的宏产品流程；研究 App 成功不能代替这两个入口的验收。

继续补齐宏模块及范围明确的实机检查，随后推进灯效与颜色。完整移植目标不缩减，本轮不开放灯效写入，也不把基础宏成功作为整套软件完成。

原始配置、USB 身份、原日志和备份仅保存在用户本机；仓库只记录验收范围及结论。

## 后续实机入口

研究入口增加五个独立场景：`ab-once`、`ab-twice`、`ab-three`、`modifier`（Shift+A）、`mouse`（鼠标中键）。每个场景仍只绑定计算器键，追加宏库并保持其他配置，分别记录写后、断电后输出及恢复。新增场景目前仅完成编译和计划／事件身份检查，未计实机通过。

原生研究 App 用 `--macro-hardware-test --macro-scenario 场景` 启动；未知场景在设备连接前拒绝。网页版研究页在首次连接前可选择场景，也可用 `macro-test.php?scenario=场景` 选择；备份后锁定选择，防止观察目标与写入目标变化。网页仍只能记录前台页面事件，不宣称设备级输出来源。研究页须按既有研究开关启用，未加入普通下载包。

首次写入前两端均禁用恢复操作，原生可直接关闭、网页可直接离开；首次写入后保留恢复与退出提示。此阶段不开放普通产品的宏写入，持续与开关仍待停止流程实机验收。

## 追加实机结果与流程修正

| 场景 | 本轮实机证据 | 未接受范围 |
| --- | --- | --- |
| AB 三次 | 写后五区与目标一致；首次输出节点通过，十二个按下／松开事件；恢复五区与原表一致 | 电源确认前或不足 15 秒时重连，整轮失败，不接受断电保留 |
| Shift+A | 写入、前后两次四事件输出、全部释放、断电后五区读回及恢复均通过；用户确认关电至重连约 31.8 秒 | 精确时序、其他修饰键组合 |
| 鼠标中键 | 写后五区与目标一致；首次输出节点通过，两个鼠标事件，原始 HID page 9 usage 3 正确转换为宏按钮掩码 4；恢复五区与原表一致 | 断电步骤未满足条件，不接受整轮通过；其他鼠标按钮 |

AB 三次和鼠标中键的旧版窗口在后续断电失败时把已经完成的输出日志追加了 cancelled，离线重放因而拒绝通过。原始日志没有改写或删除，不能称这两份保存的评估无中断通过；表格描述的是会话首次通过节点、实际事件和写入／恢复范围。此问题发生在观察完成之后，已修正为只有仍在 observing 的失败才中止当前执行证据。后续阶段仍让整轮失败，不能用局部成功覆盖错误。

两端增加明确的“本轮同时测试断电保留”选项。基础 AB 两次默认包含断电，其余独立输出场景默认只验写入、输出和恢复；可在首次写入前选择完整断电流程。结果记录 powerTestRequested，未选择时明确提示“未测试断电保留”，不伪造保留证据。原生回归检查覆盖后续失败保留已完成输出、输出范围通过但断电标志仍为 false。新版源代码已编译，正在运行的 v4 App 没有被替换。

## 持续／开关实机入口

原生与网页研究入口已接入 `held`、`toggle`，使用原计算器键绑定 AB 循环，并通过既有停止处理器进行修改／恢复。先观察至少两轮、按官方方式停止，再明确确认；确认时必须全部释放，之后的新按下使观察失败。日志保存 userAcknowledged 停止标记，不宣称捕获了固件的停止时刻。可选择同时进行断电保留；关电确认后显示 15 秒倒计时，未满时明确提示不要开电或重连。

原生窗口可以在首次写入前选择七个场景，原始备份保持不变，更新目标后锁定选择；首次写入后不能切换。原生编译及离线检查通过。浏览器实际按钮检查覆盖两种模式的目标绑定、停止按钮、明确停止标记、恢复前停止对话框、完整恢复，以及未选断电时结果明确标注未测试；使用内存设备与浏览器自动化，不计实体停止或断电通过。普通产品的宏写入仍未开放，下载包未更新。


## 持续模式已完成的一轮验收

用户暂停测试之前，独立 v6 App 的 held 会话已完成。断电前后各观察七轮 AB、28 个事件，全部释放；用户明确确认停止后没有新事件，两份评估通过。用户确认关闭电源至重连约 23.17 秒，写后与重连的五区配置均等于目标，恢复五区等于原备份，会话 complete、passed=true。这里只接受这一轮持续模式，不推断精确时序或开关模式。

随后开关模式窗口停在 ready，尚未写入。按用户“宏模块全部完成后统一真机测试”的要求，已关闭窗口；没有新增开关模式验收证据。
