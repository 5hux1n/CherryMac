# 宏执行观察与自动评估

源码增加原生与网页共用规则的被动检查器，用于后续真机宏测试的自动判断与日志重放。它不连接设备、不发按键、不授予写入权限，也不把等待时间当作宏停止证据。当前仍未接入完整实体采集窗口，不能据此宣布宏模块或实机验收完成。

## 检查规则

指定次数模式必须观察到完整且顺序正确的事件序列，次数与配置一致；缺少事件、额外循环、重复按下、没有对应按下的松开和错误按键都会阻止通过。鼠标按钮与同数值的键盘 Usage 分开核对，例如中键和 A 都可能使用数值 4。

持续与开关模式必须至少观察到两轮完整循环，并具有显式停止标记。停止标记后只允许已按住的键释放，不允许新按下；中止时可以按不同于完整宏的顺序释放实际按住的键。释放不能掩盖其他按键的错误松开。

最后一个事件／停止标记之后，还需要持续观察一段无新事件的窗口。当前窗口为一个宏循环的事件延迟总和加 200 毫秒，最少 200 毫秒。这只是软件检查条件，不能证明固件时序、队列或任意未来时间均无输出。若窗口之后又出现事件，检查器的后续评估会反映该事件。

断线、失焦、日志失败、取消、无法解析报告或超过 65536 条记录容量会使观察不能通过。失败一旦记录，不会被之后的正常事件或较长等待清除。

## 证据范围

输出区分观察来源 `hid`、`focusedBrowser`、`simulation`；停止来源区分实体触发观察、用户完成停止动作后确认、模拟标记。来源标签来自采集方，重放日志不会独立认证设备身份或数据真实性。用户确认不能冒充测量到物理触发键的时间。

这里的 `passed` 仅表示所提供事件符合上述有限观察规则。硬件写入、实际延迟语义、设备身份、断电保留、恢复与完整产品流程需要另外提供证据；不以一个评估结果替代整项宏验收。时间间隔保留在原日志中，当前不猜测 Delay 在事件之前还是之后生效。

## 日志重放

原生工具入口：

```sh
CherryMac --analyze-macro-execution /absolute/path/assessment.json \
  --execution-log /absolute/path/execution.json
```

该入口仅读取已有日志，输出包含原文件 SHA-256 的评估报告，不打开 USB 或运行软件映射。输出不能覆盖原日志；输入最大 8000000 字节、65536 条事件。无效日志使命令失败，应检查退出状态及报告中的输入校验值，不能使用旧报告。

网页通过 `replayMacroExecutionLog` 重放相同结构。下面仅是模拟格式示例，不是实机日志：

```json
{
  "format": "CherryMacMacroExecution",
  "version": 1,
  "macro": {
    "name": "A",
    "steps": [
      {"usage": 4, "pressed": true, "delayMilliseconds": 0},
      {"usage": 4, "pressed": false, "delayMilliseconds": 50}
    ]
  },
  "playback": {"mode": "count", "count": 1},
  "source": "simulation",
  "startedMilliseconds": 0,
  "events": [
    {"usage": 4, "pressed": true, "milliseconds": 100},
    {"usage": 4, "pressed": false, "milliseconds": 150}
  ],
  "assessedMilliseconds": 400
}
```

事件采用同一单调毫秒时钟，记录按下状态的实际变化；重复报告值由采集适配器区分，不能丢弃真实事件或为了通过而重排事件。鼠标事件增加 `kind:"mouse"`。

持续／开关日志增加 `stop:{milliseconds,source}`；时间与事件相同时，重放按停止标记先发生处理。观察期间发生中断时增加 `interruptions` 数组，可取 observerDisconnected、focusLost、loggingFailed、cancelled、reportRejected。

## 检查结果与下一步

原生 17 组自测、网页核心 37 项通过；独立原生／网页重放比较 29 个正常与失败场景，另确认 6 类无效日志拒绝及原日志不可覆盖。测试数据全部模拟，不计入实体验收。

下一步将检查器接入自动保存日志的实体采集与测试窗口，继续补齐持续／开关宏的写入、停止与可恢复流程。宏代码和审查完成后，按用户授权进行真机写入、执行、断电重连与原配置恢复，再推进灯效。无需用户手工编写此日志。


## 原生只读采集窗口与受限传输（源码增量）

`Source/build-macro-observer.sh /绝对路径/CherryMacMacroObserver` 编译研究程序并运行离线自测；编译不会连接或写入键盘。只有显式启动 `--macro-output-observer --test-dir /新的绝对目录` 才打开只读窗口，核对当前 USB 设备、读取五区备份，并观察当前计算器槽位已经绑定的宏。此窗口不会创建宏、修改绑定或恢复配置，不能替代完整真机验收入口；当前不要求用户提前运行。

采集按设备筛选的 IOHID 状态变化，保留键盘／鼠标身份和原始时间；初始零值和重复状态不会虚构按下或松开。不支持的输出、失焦、断开、日志失败、取消和容量溢出阻止通过。持续／开关观察仍需至少两轮输出和明确停止标记；窗口的鼠标确认只记录用户确认，不声称测得了固件停止。目录自动保存 `baseline.json`、`session.json`、`execution.json` 和带输入 SHA-256 的 `assessment.json`。

宏传输权限另外隔离：原生只在 `CHERRY_MACRO_TEST` 编译下提供 `applyMacro`，网页只在研究程序显式构造 `CherryHID(device,{macroResearch:true})` 时提供事务方法。常规客户端和网页仍不开放宏写入。实际传输只接受计划中的精确键位／宏区包，逐包等待至少 1.5 秒、核对释放、先保存日志，再发送。原生通信发送失败、回复无效或超时后会使会话失效，阻止盲目恢复发送；重新连接和独立读取仍待完整验收程序串接。

离线证据：采集窗口的指定次数、持续／开关、重复报告、断开失败和日志重放检查通过；原生 17 组既有检查通过；网页核心增至 40 项，新增实际 CherryHID 类搭配内存设备的报告封装、头部最后写入、完整读回、逐包等待、越界拒绝、日志失败、超时停止及授权撤销检查。没有进行实体宏写入、执行或断电测试，也没有更新发布包。持续／开关事务的停止／恢复、完整测试入口和官方扩展动作仍需完成。
