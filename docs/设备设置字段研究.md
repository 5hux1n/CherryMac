# 设备设置字段研究

分析对象：本地官方 Utility 2.3.28.7 安装包中的主程序、默认配置及界面资源。未运行 EXE，未写入键盘。

型号 47 在五份默认配置中均含 `SystemStages`。其 `DeviceBasicInfo` 是通用模板资料，不能代替实际 USB 046A:01CE 身份。

主程序 JSON 设置函数 `0x482E70` 将参数中的七个 UInt16 写入对象 `+0x4A8`，并更新 JSON。读取函数 `0x483100` 从 JSON 取数，构造同样的 14 字节结构。确认的结构顺序如下；这些偏移不是 USB 参数偏移。

| JSON 字段 | 结构字节偏移 | 后续待核对 |
| --- | ---: | --- |
| Repeat | 0 | 实际范围、时间单位、主机或固件处理 |
| RepeatDelay | 2 | 实际范围、时间单位、主机或固件处理 |
| Key6Flag | 4 | 可见控件、模式语义、型号写入路径 |
| ReportSelectItem | 6 | 型号支持的 USB 回报率、写入路径 |
| RFReportSelectItem | 8 | 无线回报率、型号支持与写入路径 |
| WFlag | 10 | 标志含义及写入路径 |
| WinFlag | 12 | 锁定语义、可见控件及写入路径 |

两端新增纯 JSON 解析函数，按已确认的 UInt16 范围验证七个字段，保留其未知附加字段。这里的 0…65535 是序列化结构范围，不能作为用户界面的有效值范围。导入不会据此修改 USB 参数、系统重复设置或创建写包。

公共参数构造路径 `0x500A77` 调用此读取函数，将 ReportSelectItem／RFReportSelectItem 的低字节分别放入 64 字节工作区的 53／54 位置。不过后续发送按型号分支执行；一般分支只更新位置 0…8、21 和 24。`0x00CE`、`0xC0CE` 与目标 `0x01CE` 不相同，不能据相似 PID 直接采用其他型号的完整参数写入。需要继续追踪目标型号的设备设置专用路径及控件显隐。

主程序 IAT `0x6EBF34` 对应 `SystemParametersInfoW`。此次检查其 20 个直接调用，未见键盘速度／延迟设置动作；所见调用主要读取界面系统参数。这不足以证明没有动态、DLL 或固件路径，也不能把 JSON Repeat／RepeatDelay 判为 Windows 系统设置。

原生和网页离线检查覆盖七字段顺序、超过一个字节的值、数字字符串、非法类型／范围拒绝，以及导入时 USB 参数不变、模板未知字段和导出保留。尚无设备设置的实体执行或断电证据。


继续追踪虚函数分派后，识别到 `CEevisionKeyboardDevice` 表 `0x77F604`：`+0x2BC` 指向公共参数发送函数 `0x500790`，`+0x300` 指向 `0x4FB2F0`。后者调用对象 `+0x4000` 内配置对象的虚函数 `+4`，不是直接 USB 发送。构造函数明确将该成员构造为 `CKeyboardProfiledata`；其表 `0x77D174` 的 `+4` 是 `0x47CAC0`，再通过 `+8` 的 `0x47C9A0` 处理 JSON 并进入文件保存路径 `0x485330`。

回报率更新还向窗口发送 `0xC19` 消息，`0x493B81` 路径继续转发给子窗口。这里的 `0xC19` 是 Windows 窗口消息，不能直接当作 USB 命令。还须确认型号 47 实际创建的类及完整应用链，静态识别通用类表不能证明它就是目标型号最终分派表。

仓库提供标准库工具 `Tools/inspect-official-settings.py`，只读本地 EXE 的 PE32、RTTI 和函数指针，固定 SHA-256 后才采用本版本地址。运行示例：

```sh
python3 Tools/inspect-official-settings.py /绝对路径/CHERRY-Utility-Software.exe
python3 Tools/test_inspect_official_settings.py
```

本地原文件的指针／类核对通过；四项合成 PE 检查覆盖 RTTI、文件与映射边界、架构和节数量，以及版本校验值不符拒绝。输出不包含程序内容、用户配置或按键日志；原 EXE 和反汇编仍保留在私有工作目录。工具不执行程序，不连接设备，不证明设置已生效或断电保留。

### 2026-10-05：相同成员偏移对应不同设置结构
