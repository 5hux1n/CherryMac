## 后续逆向的线索

目标镜像含 `led_define_1` 至 `led_define_8`、`kb_matrix_1` 至 `kb_matrix_8`、`macro_data_1` 至 `macro_data_48`，以及对应 flash 路径。它们是固件中的存储名称线索，不直接证明可用配置组数、每宏容量、主机 bank 编号或断电保存行为；现有发送授权及宏容量不因此扩大。

三个具名字符串都有按四字节对齐的指针候选，地址等于镜像内偏移加 `10000`。这一候选链接基址用于定位 ARM Thumb 代码与数据的关系，仍需控制流和加载布局验证。初步只读反汇编已经能定位存储名称比较及回调片段；字面量池不能当作指令，片段也不能替代完整的报告接收／写入／保存链。

## 报告分派与宏边界（静态工具 v2）

定位到链接地址 `2F094` 的报告分派入口：从输入 byte3 取命令、byte4 取长度、byte5 取 16 位偏移，数据从 byte8 起；其具名路径检查 report ID 为 4。`2F0F0` 使用 Thumb 半字跳转表，表起点 `2F0F4`，174 项覆盖命令 03…B0。工具直接从真实表计算目的地址，并核对完整表摘要；不将表或字面量池反汇编出来的伪指令当作代码。

| 命令 | 固件分支地址 | 与现有实现的对应项 |
| --- | --- | --- |
| 03 | 2F3A2 | 设备资料读取 |
| 05 / 06 | 2F3BA / 2F250 | 参数读取／更新 |
| 07 / 08 / 09 | 2F3D6 / 2F3F4 / 2F412 | 默认键位／当前键位读取、键位更新 |
| 0A / 0B | 2F43E / 2F45C | 配色读取／更新 |
| 14 / 15 | 2F496 / 2F4B4 | 宏区读取／更新 |

宏读、写两个分支均要求 offset < C00 且 offset+length < C00，等于边界也拒绝。因此，从偏移 0 连续覆盖的最大字节数是 3071，与当前产品范围吻合；不是将容量扩展为 3072。更新分支从 payload 复制到目标 RAM 并设置状态字节；复制助手 `3A084…3A0EC` 的完整代码已核对为带对齐处理的字节／字复制。状态字节的后续保存与完成语义仍需继续追踪。

另逐一核对 64 组存储名称与相邻 RAM 指针：八个灯效项从 `20000D18` 起、八个键位项从 `20000A98` 起、48 个宏数据项从 `200054EC` 起，同组相邻地址均相差 64。结合已阅读的名称比较／长度检查片段，这是以块定位配置 RAM 的线索；48 个名字不表示允许 48 个宏，也不直接证明 flash 保存完成或主机可访问配置组数量。
