## 直接读取后的单键编辑缺口

以下记录历史缺口，0.73.0／Web 0.72.0 已接入 hardwareRGB 底板和 lightingRawSlots 位置来源。此前原生 paletteEditable 与网页 paletteEditable 均要求 officialRGB。直接硬件读取标记 hardwareRGB；用户不能仅改一个键而保留现有底色，必须导入已知原色或新建空白配色。这个来源约束避免重复缩放，但不等于完整满足按键逐个调色的产品目标。

当前位置来源已接入；Mac 0.74.0／Web 0.73.0 补齐模板合并与完整编码比较，逐键来源便携文件升级为配置格式 v2，使旧客户端拒绝而非丢掉来源。旧 v1 文件仍可读，带位置记录者在导出时升级；缓存资料的 v2 是独立格式。跨端收藏 JSON 迁移入口现已接入，独立未写入草稿保存与匹配原色缓存已分开接入；保存按钮适用检查已接入；下一项继续官方可见功能与灯效整体离线核对。实现要求：未改动位置保持已读取的存储 RGB，用户明确改变的位置按官方亮度编码；不能把整个已处理颜色表当原始颜色重新缩放，也不能选择一个反推值冒充原色。来源记录须贯通两端草稿校验、单键／批量编辑、亮度、候选计划、缓存、恢复和 CherryMac JSON。Windows 导出仅在原始资料足以证明等价编码时开放，否则明确说明并提供无损的 CherryMac 草稿保存。必须保留读取到的 LED 映射核对、原始备份和现有发送范围。新模型只做离线开发，最终统一真机验收。

## 普通应用与恢复默认的阶段区别

工具 v74 固定按钮比较／调度／计时器清理／普通处理器四段代码摘要及目标类虚表。light_butt_prosave 的相等分支调用4b17e0(0)，请求计时器0409（10ms）；48b073清理该计时器后调用4b1930。普通处理器先调用设备虚表+2bc，本型号对应500790参数方法；读取LightInfo后仅当官方SelectItem==21（本型号自定义逐键索引）才继续调用+2c4，对应501190颜色方法。两端 Source/WindowsProfile.swift／Web/assets/model.js 现有普通候选计划已保留参数→配色；默认灯效恢复使用另行分析的配色→参数路径，不统一改序。普通处理器没有在这段直接逻辑中检查参数方法的返回值；不能将官方顺序等同于故障安全证明。完整消息跳表可达性、回调、方法内部完整副作用和固件持久化仍分别待核对；产品及设备行为均未运行。
